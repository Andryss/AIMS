# Стиль проекта

- Продолжать существующую структуру контроллеров, сервисов и репозиториев; контракты API менять в OpenAPI, сгенерированные классы вручную не редактировать.
- Переиспользовать общие параметры и дефолты OpenAPI. Не дублировать их числами или Java-константами в контроллере, если Spring уже подставляет значения.
- Выбирать простое решение без дублирования логики. Если дата заполняется БД, настроить JPA соответствующим образом вместо ручного заполнения в сервисе.
- Роли и права описывать в enum и инициализировать существующим DemoDataInitializer. Для обновления локальной демо-БД добавлять права адресно; не вводить для этого отдельные SQL-миграции и не менять инициализатор без запроса.
- Тесты дополнять в существующем стиле. Наборы независимых входных данных проверять параметризованными тестами вместо циклов; не добавлять тесты DemoDataInitializer для обычного API.
- Не добавлять сведения о реализованных прецедентах в README и другие документы без запроса.
- Во frontend переиспользовать UI-компоненты и CSS-токены. Для справочников использовать таблицу с переходом в карточку; создание и редактирование — в модалке с предзаполнением при редактировании.
